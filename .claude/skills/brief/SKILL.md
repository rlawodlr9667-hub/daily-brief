# 아침 경제뉴스 브리핑

수집·발송은 파이썬이, 요약과 소견은 네가 담당한다.

**항목은 5개다.** 사용자가 텔레그램 버튼으로 골라 보는 구조이므로, **항목마다 독립된 파일**을 만든다. 사용자는 한 항목만 볼 수도 있으니 각 파일이 그 자체로 완결되어야 한다.

| 내부이름 | 항목 | 다루는 내용 |
|---|---|---|
| `kr_stock` | 국내증시 | 코스피·코스닥, 수급, 종목·실적, 공모주 |
| `us_stock` | 미국증시 | 뉴욕증시, 연준·FOMC, 미국 빅테크 실적 |
| `commodity` | 유가·원자재 | 국제유가, 금·구리·리튬, 천연가스, 곡물 |
| `realestate` | 부동산 시장 | 집값·전셋값, 거래량, 청약·분양, 재건축 진행 |
| `re_policy` | 부동산 정책 | 세제, 대출규제(LTV·DSR), 공급대책, 국토부 발표 |

## 1단계 — 뉴스 수집

```
python fetch_news.py
```

`data/raw_<날짜>.md` 가 만들어진다. 출력 마지막 줄에 실제 경로가 찍히니 그 경로를 쓴다.

- 출력에 항목별 **매체 구성**이 함께 표시된다. 한 매체가 몰려 있으면 사용자에게 알린다.
- 피드 일부 실패는 정상이다. 절반 이상 실패했으면 알린다.
- 수집량이 너무 적으면 (항목당 3건 미만이 여러 개) `python fetch_news.py --hours 48` 로 다시 시도한다. 주말·연휴에 흔하다.
- "기사를 한 건도 가져오지 못했습니다" → 인터넷 문제다. 멈추고 알린다.

## 2단계 — 원본 읽기

`data/raw_<날짜>.md` 를 읽는다. 항목별로 나뉘어 있고 각 기사에 제목·출처·시각·내용 발췌·링크가 있다.

**`N개 매체 동시 보도`를 주목한다.** 여러 언론사가 같은 사건을 다뤘다는 뜻이므로 그날의 중요 뉴스다. 거의 항상 넣는다.

다음은 **넣지 않는다**:

- 정부·기관 보도자료 성격 (`공모`, `모집`, `선정`, `개최`)
- 광고성 기사 — 특히 증시 항목의 `스탁론`·`리딩방`, 부동산 항목의 특정 아파트 분양 홍보
- 재난·사건사고, 지역 행사
- 개인 재무상담·생활기사 (해외 피드에 섞여 들어온다)

## 3단계 — 항목별 브리핑 작성

`briefs/<날짜>/` 폴더를 만들고, 그 안에 **내부이름으로 파일 5개**를 쓴다.
예: `briefs/2026-07-26/kr_stock.md`

파일명은 반드시 위 표의 내부이름과 같아야 한다. 버튼이 이 파일명으로 찾는다.

기사가 아예 없거나 쓸 만한 게 하나도 없는 항목은 **파일을 만들지 않는다.** 그러면 그 버튼이 메뉴에서 자동으로 빠진다. 억지로 채우지 않는다.

### 각 파일의 구조

```markdown
## 📈 국내증시 — 7월 26일 (일)

**1. 제목을 그대로 쓰지 말고 핵심을 담아 다시 쓴다**

2~3문장으로 요약한다. 무슨 일이 있었고, 숫자가 어떻게 되고, 왜 중요한지까지.
🔗 [한국경제 원문](링크) · 3개 매체 보도

**2. 다음 기사**

...

> 소견: 이 항목 기사들을 묶어 "그래서 무슨 의미인가"를 3~4문장으로 쓴다.
```

첫 줄은 반드시 `## <이모지> <항목명> — <날짜>` 로 시작한다. 사용자가 버튼을 눌러 이것만 받으므로, 무엇에 대한 글인지 스스로 밝혀야 한다.

### 작성 원칙

지킬 것:

- **항목당 기사 3~5건.** 원본에 14건이 있어도 다 쓰지 않는다. 쓸 만한 게 2건뿐이면 2건만.
- **숫자를 반드시 넣는다.** 지수 몇 포인트, 유가 몇 달러, 집값 몇 %, 금리 몇 %. 숫자 없는 요약은 쓸모없다.
- **기사마다 원문 링크를 붙인다.** `🔗 [매체명 원문](링크)` 형식으로 눈에 띄게.
- **출처를 밝힌다.** 어느 언론사 보도인지 항상 적는다.
- **`> 소견:` 이 이 브리핑의 존재 이유다.** 요약을 반복하지 말고, 기사에 없는 연결과 판단을 담는다.
- 해외 기사는 한국어로 옮겨 요약한다. 영어 제목을 그대로 두지 않는다.
- 확실하지 않은 것은 "~로 보인다", "~라는 관측이 나온다"로 쓴다.

하지 말 것:

- **투자 권유 금지.** "지금 사야 한다", "오를 것이다"를 쓰지 않는다.
  "증권가에서는 ~라는 전망이 나온다"처럼 누구의 판단인지 밝힌다.
  부동산도 같다. "지금이 매수 타이밍" 같은 표현을 쓰지 않는다.
- 기사 제목만 나열하지 않는다.
- 원본에 없는 사실을 만들어 넣지 않는다. RSS 발췌문이 짧아 내용이 부족하면
  짧게 쓰거나 빼고, 억지로 채우지 않는다.
- 한 항목이 4,000자를 넘지 않게 한다. 넘으면 자동 분할되지만 읽기 부담이 커진다.

## 4단계 — 확인받고 메뉴 발송

1. 작성한 항목 목록과 각 항목의 기사 수를 사용자에게 보여준다.
2. 브리핑 내용도 보여준다 (최소한 사용자가 관심 있어 할 항목은).
3. **메뉴를 보내도 되는지 물어본다.** 묻지 않고 보내지 않는다.
4. 승인하면:

```
python bot_server.py --send-menu
```

버튼 메뉴 톡 한 건이 발송된다. 브리핑 본문은 사용자가 버튼을 눌렀을 때 전송된다.

5. 발송 후 **버튼 응답 프로그램이 켜져 있어야 한다**는 점을 알린다:

```
python bot_server.py
```

이미 실행 중인지 모르겠으면 `python bot_server.py --once` 로 대기 중인 클릭만 처리해 볼 수 있다.

### 문제 상황

- `config.json 파일이 없습니다` → 텔레그램 설정 전이다. `python setup_telegram.py <봇토큰>` 을 먼저 하라고 안내한다. 토큰은 사용자만 만들 수 있다.
- 특정 항목 브리핑만 바로 보내달라고 하면 `python send_telegram.py briefs/<날짜>/<내부이름>.md` 를 쓴다.
- 발송 전 변환 결과를 확인하려면 `--dry-run` 을 붙인다.
